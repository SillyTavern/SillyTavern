# Response Prompt Processing Enum for Image Generation

**Date:** 2026-07-11
**Status:** Approved (pending spec review)
**Scope:** `public/scripts/extensions/stable-diffusion/` — settings, UI, and prompt processing logic

## Problem

The Stable Diffusion extension's `processReply()` function sanitizes image generation prompts returned by an LLM. The "Minimal response prompt processing" checkbox (`minimal_prompt_processing`) reduces this processing, but even in minimal mode the code runs `str.replace(/\s+/g, ' ')` — and `\s` matches `\n`, so **newlines are always stripped**. There is no way to get the raw LLM output unmodified.

## Goal

Replace the boolean `minimal_prompt_processing` setting with a three-state enum `prompt_processing` that supports an `"off"` mode returning the prompt completely untouched (newlines preserved).

## Enum Values

| Value | Behavior |
|-------|----------|
| `"standard"` | Full processing (default; current `false` behavior) |
| `"minimal"` | Reduced processing (current `true` behavior) |
| `"off"` | No processing — return `str` unchanged |

## Design

### Setting & Migration

**Default settings** (`index.js`, `defaultSettings` object ~line 283):
- Remove: `minimal_prompt_processing: false`
- Add: `prompt_processing: 'standard'`

**Migration** (in `loadSettings` / the settings init function, inserted **before** the "Insert missing settings" loop at ~line 468):
```js
if (extension_settings.sd.prompt_processing === undefined
    && extension_settings.sd.minimal_prompt_processing !== undefined) {
    extension_settings.sd.prompt_processing =
        extension_settings.sd.minimal_prompt_processing ? 'minimal' : 'standard';
    delete extension_settings.sd.minimal_prompt_processing;
}
```
The existing "Insert missing settings" loop then fills in `prompt_processing: 'standard'` for fresh installs with no saved setting at all.

### `processReply()` (`index.js` ~line 2896)

Add an early-return branch for `"off"` at the top of the function (after the existing empty-string guard):
```js
if (extension_settings.sd.prompt_processing === 'off') {
    return str;
}
```
Replace the `if (extension_settings.sd.minimal_prompt_processing)` check with:
```js
if (extension_settings.sd.prompt_processing === 'minimal') {
```
The `"standard"` path remains the implicit fallthrough (unchanged logic).

### UI (`settings.html` ~lines 38-41)

Replace the checkbox `<label>` block with a select dropdown:
```html
<label for="sd_prompt_processing" data-i18n="[title]sd_prompt_processing"
       title="Controls post-processing on prompts generated by the LLM. Off preserves raw output including newlines.">
    <span data-i18n="sd_prompt_processing_txt">Response prompt processing</span>
</label>
<select id="sd_prompt_processing" class="text_pole">
    <option value="standard" data-i18n="sd_prompt_processing_standard">Standard</option>
    <option value="minimal" data-i18n="sd_prompt_processing_minimal">Minimal</option>
    <option value="off" data-i18n="sd_prompt_processing_off">Off</option>
</select>
```

### Load / Save / Event Handlers

**Load** (`index.js` ~line 547):
- Replace `$('#sd_minimal_prompt_processing').prop('checked', extension_settings.sd.minimal_prompt_processing);`
- With: `$('#sd_prompt_processing').val(extension_settings.sd.prompt_processing);`

**Save** — rename `onMinimalPromptProcessing` → `onPromptProcessingSelect` (~line 670):
```js
function onPromptProcessingSelect() {
    extension_settings.sd.prompt_processing = String($(this).val());
    saveSettingsDebounced();
}
```

**Event binding** (~line 5869):
- Replace `$('#sd_minimal_prompt_processing').on('input', onMinimalPromptProcessing);`
- With: `$('#sd_prompt_processing').on('change', onPromptProcessingSelect);`

### Slash Command Argument Handling (`index.js` ~lines 5407, 5410-5417)

**`settingMap`** entry:
- Change `'processing': 'minimal_prompt_processing'` → `'processing': 'prompt_processing'`

**`enumHandlers`** for `'processing'`:
```js
'processing': (value) => {
    if (/standard/gi.test(String(value))) {
        return 'standard';
    }
    if (/minimal/gi.test(String(value))) {
        return 'minimal';
    }
    if (/off/gi.test(String(value))) {
        return 'off';
    }
},
```

### i18n

The new `data-i18n` keys in `settings.html` carry inline English text (the HTML text content acts as the default). The existing `sd_minimal_prompt_processing` / `sd_minimal_prompt_processing_txt` keys in `zh-cn.json` become unused but are harmless left in place — translators can add the new keys and remove the old ones at their discretion.

## Impact on `processReply` Call Sites

`processReply` is called in three places; all benefit from the new `"off"` mode consistently:

1. `generatePrompt()` (`index.js:3295`) — the primary LLM-generated prompt path; this is the user's main use case.
2. `getRawLastMessage()` (`index.js:2955`) — raw last chat message used in free mode.
3. `getRawLastMessage()` (`index.js:2958`) — character scenario + description concatenation.

With `"off"`, all three return raw text, which is the expected "no processing" behavior.

## Out of Scope

- Updating non-English locale files beyond leaving stale keys (translators handle that).
- Changes to the ComfyUI workflow editor or other unrelated extension settings.
- Any changes to how the LLM *generates* the prompt — this only affects post-processing of the reply.
